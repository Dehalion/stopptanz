# PlaybackService is the source of truth for Session state; Activity always-binds at launch

Rotation/config-change was killing an in-progress Session: `MainActivity` only bound to `PlaybackService` inside the Start-Session button's `onClick`, holding `sessionState`/`boundService`/`serviceConnection` in plain `remember {}` state that doesn't survive Activity recreation — after rotating, the service kept running (orphaned, zero bindings) but the UI reset to "no session," with no way back in. Considered a ViewModel (`sessionState` etc. as ViewModel state, surviving recreation via `viewModel()`) as the alternative fix, but `PlaybackService` was already designed and documented as owning Session lifetime independent of the Compose tree — a ViewModel would duplicate that source of truth rather than just reading it. Decision: the Activity binds to `PlaybackService` once at launch (`LaunchedEffect`, torn down only in `onDispose`) and keeps that single binding for its whole lifetime; Start/Stop/Resume/Done call methods on the already-bound service instead of creating/tearing down the connection themselves. This makes the service the sole source of truth for Session state — the Activity (and any future UI) just observes it.
